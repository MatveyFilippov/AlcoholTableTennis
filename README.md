# Alcohol Table Tennis

ATT записывает результаты одного вечера настольного тенниса. Участники могут добавлять игроков, матчи, этапы и напитки без регистрации. История и статистика открыты, исправления доступны администратору.

## Запуск локально

Нужен Docker с Compose v2. В корне репозитория выполните:

```sh
docker compose up --build --wait
infra/scripts/smoke.sh http://127.0.0.1:8080
```

Приложение доступно на [localhost:8080](http://127.0.0.1:8080), [интерактивная документация API](http://127.0.0.1:8080/api/docs) и [схема OpenAPI](http://127.0.0.1:8080/api/openapi.json) включены для локальной среды. PostgreSQL хранит данные в именованном томе. Команда `docker compose down` останавливает приложение и сохраняет том.

Для локальной разработки запустите PostgreSQL 16, укажите `DATABASE_URL` (драйвер `postgresql+psycopg`) и выполните из `backend/`:

```sh
python3.12 -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
alembic upgrade head
ATT_DOCS=1 ATT_INSECURE_LOCAL=1 uvicorn att.main:app --port 8000
```

В отдельном терминале из `frontend/` с Node.js 22 выполните `npm ci` и `npm run dev`. Vite проксирует запросы к API. Для проверки входа сгенерируйте Argon2id-хеш командой `python -m att.hash_password` и передайте его через переменную окружения `ADMIN_PASSWORD_HASH`.

## Как записать матч

1. Создайте два псевдонима на странице «Игроки». Начальный этап — «Трезвые».
2. В «Записать матч» выберите игроков и формат до 11 или 21. Подтвердите итоговый счёт. На этапе №0 действует исходная оценка 0. На следующих этапах укажите самооценку каждого либо «Неизвестно».
3. Чтобы вести очки по ходу игры, откройте «Счётчик матча». Черновик сохраняется в браузере и публикуется после подтверждения результата. При сбое сети повторите отправку из того же черновика.
4. Этапы и напитки добавляются на странице «Алкоголь». Добавление этапа само по себе не меняет потребление игроков.

## История и рейтинги

Время начала используется для отображения. Elo обновляется по порядку публикации, с начальным рейтингом 1000 и K=32. Трезвый Elo обновляется отдельно, когда обе оценки равны 0 и оба участника на момент начала матча имеют 0 г этанола. Этанол рассчитывается из объёма и крепости напитка. Графики показывают описательную статистику.

Сервер присваивает общий порядковый номер в транзакции под блокировкой строки PostgreSQL. Снимок счётчика сохраняет номер на начало матча. При чтении API восстанавливает накопленные граммы по событиям до этого номера и пересчитывает Elo из действующих матчей. Исправления сохраняют порядковый номер и добавляют запись в журнал. Снимок для быстрого ввода нужно обновить при изменении вечера. Идемпотентность записей хранится на протяжении жизни вечера, чтобы неопределённый ответ не привёл к повторной записи.

## Проверки

- Сервер — из `backend/` выполните `ruff check .`, `ruff format --check .`, `mypy att/rules.py att/schemas.py att/db.py` и `pytest -q`. Для интеграционных проверок укажите `ATT_TEST_DATABASE_URL` на отдельную БД с именем, оканчивающимся на `_test`. Фикстура очищает таблицы в этой БД.
- Клиент — из `frontend/` выполните `npm run lint`, `npm run typecheck`, `npm test` и `npm run build`.
- Браузер — запустите локальный стек, затем из `frontend/` выполните `npm exec -- playwright install chromium` и `npm run e2e`. Тесты создают записи. Используйте отдельный тестовый стек.
- Compose и сценарий релиза — `docker compose config --quiet`, `docker compose build`, `infra/scripts/check-infra.sh`.
